# ADR-0001. Окно звонка — встроенный веб-клиент с заменённым signaling.js

Статус: принято · 2 ноября 2026

## Контекст
Приложение обязано звонить по ссылкам веб-версии. Логика звонка веба (perfect negotiation, тайминги, TURN, мост,
группы, чат и файлы в звонке) — десятки версий доработок. Порт на свой движок — риск расхождений и много работы.

Интерфейс веба к транспорту очень узкий: `app.js` создаёт `new Signaling({topic, key, selfId, inst, …, onMessage,
onStatus, onPeerJoined})` и вызывает только `start()`, `send(msg, opts)`, `sendByeBeacon()`, `deliveryStats()`,
`close()`, `onTransportUp`.

## Решение
- В приложение кладём копию веб-клиента закреплённой версии (`ui/web`, `tools/sync-web.sh`, коммит в `ui/web/WEB_VERSION`).
- Заменяем только `signaling.js` на мост к ядру (`ui/desktop/signaling.js`): конверт, шифрование, каналы, дедупликация —
  в Rust (`zv-signal`). Экспорты `ntfyWanted`, `ntfyTopicForSignaling` сохраняем.
- `ui/desktop/preload.js` (скрипт инициализации окна): прокси `fetch` к Worker через ядро (Worker отвергает чужой Origin),
  заглушка service worker, автоматический вход при ответе на входящий, имя из профиля, возврат в оболочку после звонка.
- Ядро дописывает в исходящие `hello`/`hi` поля приложения (`app`, `zv`) и добавляет канал `p2p` между приложениями.

## Последствия
+ Совместимость максимальная: звонок, группы, чат, файлы, мост — это код веба. `ver` совпадает со встроенной версией.
+ M1/M5 сильно короче. Обновление веба = синхронизация копии + E2E.
− Связь с внутренностями `app.js` (имена элементов, route()). Контролируем E2E и ночным тестом.
− Окно звонка выглядит как веб; своя оболочка — для ссылок, контактов, чатов, настроек.
