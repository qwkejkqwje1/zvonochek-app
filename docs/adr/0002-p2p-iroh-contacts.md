# ADR-0002. P2P между приложениями: только iroh (libp2p отложен), контакты через ключи устройств

Статус: принято · 2 ноября 2026

## Контекст
План (ARCHITECTURE §4) предполагал два P2P-стека: iroh (основной) и libp2p (DHT-рандеву, TCP, свои релеи).
На M3 нужно: звонки контактам без ссылок, «в сети», ответ при закрытом окне, апгрейд звонка между приложениями на P2P,
голос моста по P2P. Ограничения: только бесплатная инфраструктура, установщик небольшой, Android следом.

## Решение
- **Один стек — iroh 1.4** (`crates/zv-p2p`, ALPN `zv/4`): QUIC, пробитие NAT, релеи n0, поиск по ID через DNS n0.
  Кадры — JSON с префиксом длины (≤ 256 КБ), голос — QUIC-датаграммы. Включается/выключается в настройках на лету.
- **libp2p отложен.** Его роль «второго независимого пути» уже закрывают имеющиеся каналы сигнализации
  (MQTT/Worker/Nostr/ntfy): через них идут звонок контакту (`ring`) и рукопожатие контакта, если iroh не соединился.
  libp2p добавил бы ~3–5 МБ и второй комплект NAT-логики при небольшом выигрыше. Вернёмся, если релеи n0 станут
  недоступны в целевых сетях (интерфейс `zv-p2p` позволяет добавить второй транспорт).
- **Личность:** мастер-сид (identity.dat, DPAPI) → HKDF → ключ iroh; ID устройства = EndpointId (Ed25519).
- **Контакт** = ID собеседника. Секрет пары — X25519 из ключей двух устройств (Ed25519→Montgomery) → HKDF; им
  запечатываются сообщения через «ящики» (комнаты сигнализации). Ящик контакта — комната, которую слушает его
  приложение (`inbox`), обмен ящиками — при добавлении.
- **Добавление:** код `zv4c:` (ID, адреса, имя, секрет приглашения, срок 7 дней) → `contact_req` с меткой
  HMAC(секрет, ID отправителя‖ID получателя) по P2P и через комнату приглашения → `contact_ok`. Из истории звонка
  по ссылке — `contact_offer` (только собеседнику из звонка за последние 24 ч), подтверждает получатель.
- **Звонок контакту:** новый секрет комнаты на каждый звонок; `ring` по P2P и через ящик (повтор 3–6 с, тайм-аут 45 с),
  `ring_ack/accept/decline(dnd)/cancel`. Комната звонка привязывается к P2P-линку доказательством
  HMAC(подключ комнаты, ID‖ID) — окно звонка (веб-клиент) не знает о P2P.
- **Проверка:** код безопасности (5 эмодзи + 6 цифр от двух ID) сверяется голосом; отметка «проверен».

## Последствия
+ Меньше кода и зависимостей; один путь NAT-пробития, который хорошо работает «из коробки».
+ Без n0 (релеи/DNS недоступны) остаются прямые адреса из кода/hello и ящики через сигнализацию.
− Поиск контакта по ID зависит от DNS n0; при его недоступности — только известные адреса.
− Нет офлайн-доставки звонка (это нормально: звонок — только онлайн); офлайн-сообщения — в M4.
