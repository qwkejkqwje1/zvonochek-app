# ADR-0006. Windows: только переносная версия, пароль профиля, самообновление заменой exe

Статус: принято · 3 ноября 2026

## Контекст
Для Windows было два вида: установщик NSIS (данные в AppData, автообновление плагином Tauri) и переносной exe (данные
рядом с exe, обновление вручную). Нужно одно: программа без установки, которую можно держать в любой папке или на
флешке и переносить вместе с данными, с автообновлением. Секреты профиля были под DPAPI — папка, унесённая на другой
компьютер, там не открывалась. Ограничения прежние: только бесплатное, без своего сервера.

## Решение
- **Только переносной exe.** Установщика нет (`tauri build --no-bundle`), плагин updater убран. Все данные — в
  `ZVONochek-data` рядом с exe (portable.rs). Нельзя писать рядом с exe — окно с объяснением и выход (тихий уход в
  AppData путал бы, где данные). Первый запуск копирует данные установленной версии из AppData. Нет WebView2 — окно со
  ссылкой на загрузку Microsoft.
- **Ключ данных профиля** (zv-core `vault.rs`). Секретные файлы (`identity.dat`, `contacts.dat`, `links.dat`,
  `import.pending`) шифруются случайным ключом данных: `ZVK1 ‖ nonce ‖ XChaCha20-Poly1305` (имя файла — связанные
  данные). Ключ лежит в `vault.json` (+ копия `vault.bak`): под DPAPI — по записи на компьютер, где он «запомнен», и,
  если задан пароль, под паролем (Argon2id 64 МиБ/3/4, как у файла переноса). Запуск: ключ запомнен здесь — сразу;
  есть пароль — окно `unlock` до запуска ядра; нет ни того ни другого (папка с другого компьютера без пароля) — окно с
  объяснением и выход. Файлы старого формата (`ZVP1`, DPAPI) перешифровываются при первом чтении. Ключ данных не
  меняется: смена пароля перешифровывает только его. Без ключа или с чужим ключом ядро не стартует — иначе
  зашифрованные файлы посчитались бы испорченными и началось бы «с чистого».
- **Самообновление** (zv-core `update.rs`, app `selfupdate.rs`). `latest.json` в последнем релизе:
  `{version, notes, platforms: {windows-x64|windows-arm64: {url, size, sig}}}`; `sig` — Ed25519 над байтами exe
  (release.yml, секрет `ZV_UPDATE_KEY`; открытые ключи — `KEYS_HEX`, их может быть несколько для смены ключа).
  Ядро скачивает exe в `ZVONochek-data\update\`, проверяет размер и подпись; приложение переименовывает работающий
  exe в `ZVONochek.exe.old` (Windows это разрешает) и кладёт новый на его место — работает со следующего запуска.
  «Перезапустить» запускает новый exe с `--wait-pid` (ждёт выхода старого, иначе «один экземпляр» отдал бы запуск
  ему же); `.old` удаляется после успешного запуска. Автообновление (по умолчанию включено): через 2 минуты после
  запуска и раз в 6 часов.

## Последствия
- Обновление не требует прав администратора и не трогает реестр; работает и на флешке (папка должна быть доступна
  для записи).
- Переписка (`chats.db`, SQLite) пока не зашифрована ключом данных — следующий шаг.
- Пароль профиля не восстановить: забыт — профиль открывается только там, где ключ запомнен.
- Если репозиторий с кодом закрыт, файлы релиза должны лежать в открытом (`ZV_RELEASE_REPO`): `MANIFEST_URLS`
  проверяет оба адреса по очереди.
- Установленные ранее версии (NSIS) сами на переносную не переходят: скачать exe, запустить — данные скопируются из
  AppData.
