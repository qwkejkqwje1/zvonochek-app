# ADR-0005. Android: то же ядро и интерфейс, фоновая служба вместо push (M6)

Статус: принято · 3 ноября 2026

## Контекст
M6 (ARCHITECTURE, «M6 Android»): приложение для Android из того же кода — Tauri 2 mobile, звонок доходит на телефон с
выключенным экраном, полноэкранный входящий, APK в GitHub Releases. В плане входящие шли через FCM (бесплатный Firebase
и отправка пушей из нашего Worker). Ограничения прежние: только бесплатная инфраструктура, без своего сервера.

## Решение
- **Один код.** Крейт `app` стал библиотекой `zvonochek_lib` (staticlib/cdylib/rlib) + тонкий `main.rs` для ПК; всё,
  чего нет на телефоне (трей, автозапуск, обновления, один экземпляр, отдельные окна), — под `cfg(desktop)`.
  Ядро (`zv-core`, P2P, чаты, группы) и интерфейс (`ui/shell` + встроенный веб-клиент) — те же.
- **Одно окно** (`wins_mobile.rs`): оболочка и звонок в одном WebView; звонок открывается переходом на
  `/web/index.html?zvboot=…`, по завершении — обратно в оболочку. Оболочка в режиме `body.mobile`: нижние вкладки,
  нет трея и «Показать в папке» (вместо — «Поделиться»), «Назад» закрывает диалог/чат, иначе сворачивает приложение.
- **Фон без push:** служба переднего плана `ZvService` (`specialUse`, подтип «ожидание входящих звонков»; на время
  звонка добавляются `microphone|camera`) с тихим уведомлением «ждёт звонков». Ядро держит те же каналы, что на ПК
  (MQTT/Worker/Nostr/ntfy + iroh). Один раз просим разрешение на уведомления и исключение из оптимизации батареи.
  В настройках — «Работа в фоне» (системные настройки батареи), «Экономный режим» (комнаты ожидания держат по одному
  MQTT-брокеру и Nostr-реле вместо двух; Worker, ntfy и P2P — как обычно; по умолчанию выключен — надёжность входящих
  важнее) и «Выйти» (останавливает службу и ядро).
- **Входящий:** ядро → плагин `zvandroid` (Kotlin) → полноэкранное уведомление (канал с мелодией, повторяется до
  ответа) с кнопками «Отклонить» и «Ответить»; поверх экрана блокировки (`setShowWhenLocked`/`setTurnScreenOn`).
  Кнопки уведомления вызывают ядро через JNI (`ZvNative.incomingAction` → `call_answer`/`call_decline`); если
  приложение на экране и не в звонке — обычное окно входящего в оболочке.
- **Пересоздание Activity** (поворот, смена темы, возврат из фона после выгрузки WebView) — `ZvNative.activityRecreated`
  заново создаёт окно, ядро продолжает работу.
- **Файлы:** выбор — системный `ACTION_OPEN_DOCUMENT` (копия в кэш приложения), принятые — в данных приложения
  (`Downloads`), «Открыть» и «Поделиться» — через `FileProvider`. Профиль и переписка — в личной папке приложения
  (песочница Android, шифрование хранилища устройства); DPAPI на Android нет.
- **Обновления:** встроенного обновления нет — кнопка «Страница релизов». APK собирает CI (`android.yml`: arm64-v8a +
  armeabi-v7a, minSdk 24 / Android 7.0, targetSdk 37) и прикладывает к черновику релиза; подпись — если заданы
  секреты `ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, иначе APK неподписанный.
- **Отличие от ARCHITECTURE — без FCM.** FCM требует проекта Firebase и `google-services.json` от аккаунта владельца,
  ключа сервисного аккаунта в Worker и сервисов Google на телефоне; при этом звонок всё равно приходит через ядро.
  Служба переднего плана работает без аккаунтов и серверов. FCM можно добавить позже как «будильник» (пуш → запуск
  ядра), не меняя протокол.

## Последствия
+ Телефон — полноценное устройство: контакты, чаты, файлы, группы, звонки по ссылке и контактам, P2P.
+ Нет зависимости от Google: работает и на телефонах без сервисов Google.
− Постоянное уведомление и расход батареи на соединения (ориентир — как у мессенджеров без push).
− Без исключения из оптимизации батареи и на прошивках с агрессивной выгрузкой (Xiaomi, Huawei, Samsung) входящие
  могут задерживаться или теряться; после перезагрузки телефона приложение нужно открыть (автозапуска нет).
+ Проверки без телефона: сборка APK, `cargo clippy --target aarch64-linux-android`, интерфейс телефона —
  `zv-devhost --mobile` + `tests/e2e/devhost-mobile.mjs`.
− На устройстве не проверено: в песочнице нет Android — только сборка APK и проверки компиляции.
− Без ключа подписи APK не установить; ключ нельзя терять — обновления ставятся только поверх той же подписи.
