# ZVONochek для Windows и Android

Голосовые и видеозвонки, чаты и группы — без аккаунтов и своего сервера, совместимо с
[веб-версией ZVONochek](https://zvonochek.github.io/). Приложение **ждёт звонков по вашим ссылкам и от
контактов**: на ПК — из трея, на телефоне — фоновой службой; у вас зазвонит, даже когда окно закрыто.

## Возможности

- **Звонок по ссылке** — вставьте ссылку сайта ZVONochek (`…/zvonochek/#k=…`) или откройте `zvonochek://call#k=…`.
  Собеседник может быть в браузере или в приложении.
- **Мои ссылки** — свои постоянные ссылки: входящий звонок поверх окон с мелодией, история (входящие, пропущенные,
  исходящие), «Не беспокоить». Ссылку можно отключить, переименовать, сменить адрес.
- **Контакты** — добавление кодом приглашения (QR), «в сети», код безопасности; звонок и видеозвонок контакту без
  ссылок; приложения соединяются напрямую (P2P: iroh и libp2p — два независимых пути, соединение переходит на
  лучший и не рвётся, если один пропал; локальная сеть без интернета).
- **Чаты** — сообщения доходят и офлайн (зашифрованный почтовый ящик), «доставлено»/«прочитано», ответ, правка,
  удаление у всех, поиск; файлы и фото с прямой передачей и докачкой.
- **Группы до 6 человек** — переписка, файлы, групповые аудио- и видеозвонки; сообщения подписаны ключом устройства.
- **Перенос профиля** на другое устройство — файл под паролем.
- **Диагностика** — состояние каждого канала связи и P2P, отчёт без ключей и ссылок.
- **Windows:** переносная версия без установки (всё рядом с exe), пароль профиля — папку можно унести на другой
  компьютер, самообновление с проверкой подписи, трей, автозапуск.
- **Android:** полноэкранный входящий поверх экрана блокировки с кнопками «Ответить» и «Отклонить», без сервисов Google.

Окно звонка — тот же веб-клиент, что на сайте (видео, демонстрация экрана, чат и файлы в звонке, статистика),
но вся сигнализация идёт через ядро приложения на Rust: параллельно MQTT (WSS и TCP), Cloudflare Worker (WebSocket и HTTP),
Nostr и ntfy, с дедупликацией и тихой ротацией соединений; между приложениями — P2P.

## Установка

Скачайте файл из [Releases](https://github.com/qwkejkqwje1/zvonochek-app/releases) (x64 — обычные ПК, arm64 — ПК на
ARM, Snapdragon; Windows 10 1809+ или 11):
- `ZVONochek_<версия>_x64.exe` — ZVONochek для Windows, без установки: положите exe в отдельную папку (например,
  «Документы» или флешку) и запустите. Все данные — в папке `ZVONochek-data` рядом с ним: настройки, контакты, ссылки,
  история, переписка, журналы, профиль WebView2, полученные файлы (`Загрузки`), скачанные обновления. Если рядом с exe
  писать нельзя (Program Files, носитель только для чтения) — программа скажет об этом и не запустится. Первый запуск
  копирует данные прежней установленной версии из AppData (оригинал остаётся, удалить — Настройки → «Копия прежней
  версии»). В реестр пишется только нужное для работы: ссылки `zvonochek://`, автозапуск (если включён) и
  регистрация для уведомлений Windows (переключатель «Уведомления Windows»); «Убрать следы с этого компьютера»
  снимает всё это.
  - **Обновление** — само: ZVONochek раз в несколько часов проверяет релизы, скачивает новый exe, проверяет подпись
    проекта (Ed25519) и ставит его на место старого; новая версия работает после перезапуска (кнопка в Настройки →
    «О программе»). Выключается переключателем «Обновлять автоматически» — тогда только по кнопке.
  - **Пароль профиля** (Настройки → «Пароль профиля»): без пароля профиль открывается только на этом компьютере;
    с паролем папку `ZVONochek-data` можно унести на другой — там ZVONochek спросит пароль («Запомнить на этом
    компьютере» — больше не спрашивать там). Пароль не восстановить.
  - Нужен WebView2 Runtime (в Windows 11 и обновлённой Windows 10 уже есть; если нет — программа даст ссылку).
- `ZVONochek_<версия>_android.apk` — Android 7.0+ (arm64 и armv7). Разрешите установку из этого источника; при первом
  запуске — уведомления и «без ограничений батареи», иначе входящие могут задерживаться. Обновление — новый APK поверх.

## Приватность

- Сигналы звонка зашифрованы (AES-GCM, ключ выводится из секрета ссылки) — серверы-посредники видят только шифротекст.
- Медиа — WebRTC (DTLS-SRTP), по возможности напрямую. Сообщения и файлы — сквозное шифрование (ADR-0003, ADR-0004).
- Данные хранятся только на устройстве: Windows — папка `ZVONochek-data` рядом с exe; ключ устройства, контакты и
  ссылки зашифрованы ключом данных профиля (XChaCha20-Poly1305). Сам ключ — в `vault.json`: под DPAPI этого
  компьютера (без пароля открывается только тут) и, если задан пароль профиля, под паролем (Argon2id) — тогда
  папка открывается и на другом компьютере (ADR-0006). Переписка (`chats.db`) пока не зашифрована. Профиль можно
  перенести и файлом под паролем («Перенос на другое устройство»). Android — личная папка приложения.
- Обновления подписаны ключом проекта (Ed25519); приложение не ставит exe с чужой или испорченной подписью.

## Устройство репозитория

| Путь | Что |
|---|---|
| `crates/zv-proto` | протокол веб-версии v1: ссылки, вывод ключей комнаты, конверт seal/open; векторы совместимости |
| `crates/zv-signal` | каналы сигнализации (MQTT, Worker, Nostr, ntfy) и `RoomHub` |
| `crates/zv-p2p` | P2P-узел (iroh + libp2p): линки из нескольких путей, кадры, датаграммы, потоки файлов, крипто пар и кодов |
| `crates/zv-core` | ядро: ссылки, входящие, история, контакты, чаты, файлы, группы, профиль, прокси HTTP веб-клиента |
| `crates/zv-devhost` | ядро без окна + IPC по WebSocket + раздача `ui/` — разработка и автотесты в Chromium |
| `crates/zv-cli` | консольные проверки каналов (`probe`, `join`, `listen`) |
| `app/` | приложение Tauri 2: окна, трей, автозапуск, deep link, уведомления, обновления; `src/android.rs` — мост к Android |
| `app/gen/android` | проект Gradle для Android: MainActivity, фоновая служба, входящий, плагин `zvandroid` |
| `ui/shell` | интерфейс главного окна и окна входящего |
| `ui/web` | встроенная копия веб-клиента (`tools/sync-web.sh`); заменён только `signaling.js` → `ui/desktop/signaling.js` |
| `ui/desktop/preload.js` | мост `window.__zvIpc` во всех окнах |
| `docs/` | архитектура, ADR, журнал разработки |
| `tests/e2e` | сквозные тесты в Chromium: живой сайт ↔ ядро, оболочка, контакты, чаты, группы, профиль, режим телефона |

## Разработка

```sh
cargo test -p zv-proto -p zv-signal -p zv-core      # тесты ядра (Linux/Windows)
cargo run -p zv-devhost -- --port 8790 --ui ui       # стенд: http://127.0.0.1:8790/ — оболочка в браузере
cd tests/e2e && npm install && npx playwright install chromium
node devhost-live-call.mjs                           # звонок «сайт ↔ ядро»
node devhost-shell.mjs                               # своя ссылка → входящий → ответ → пропущенный
node devhost-chats.mjs && node devhost-groups.mjs    # чаты и группы (свои devhost и заглушка Worker)
```

Сборка приложения на Windows: `npm i -g @tauri-apps/cli@2`, затем `cd app && tauri build`.
Кросс-сборка из Linux: `tools/build-win.sh x86_64` или `tools/build-win.sh aarch64` (нужны cargo-xwin, makensis ≥ 3.9).
Android: JDK 21, Android SDK (platform 37) и NDK, `rustup target add aarch64-linux-android armv7-linux-androideabi`,
затем `cd app && tauri android build --apk --target aarch64 --target armv7` (или Actions → «Android»).

Обновление встроенного веб-клиента: `WEB_DIR=../zvonochek tools/sync-web.sh <коммит>` — скрипт проверяет,
что интерфейс `Signaling` не изменился. Ночная проверка совместимости — `.github/workflows/nightly-compat.yml`.

### Релиз

1. Один раз: в Settings → Secrets → Actions — `ZV_UPDATE_KEY` (закрытый ключ подписи обновлений, PEM Ed25519;
   открытый — `KEYS_HEX` в `crates/zv-core/src/update.rs`). Для Android — `ANDROID_KEYSTORE_B64` (ключ `.jks` в
   base64), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`; без них APK собирается неподписанным. Оба ключа хранить
   в надёжном месте: без них обновления не встанут. Если этот репозиторий закрыт, файлы релиза кладутся в открытый:
   переменная `ZV_RELEASE_REPO` (владелец/имя) и секрет `ZV_RELEASE_TOKEN` с правом записи в него (репозиторий —
   не пустой, хотя бы README: релизу нужен коммит для тега).
2. Поднять версию в `Cargo.toml` (workspace) и `app/tauri.conf.json`, дописать раздел версии в `CHANGELOG.md` (он же —
   «что нового» в окне обновления).
3. `git tag v4.0.1 && git push --tags` → Actions соберёт черновик релиза (exe x64 + ARM64, подписанный `latest.json`,
   APK) → опубликовать: с этого момента приложения увидят новую версию.
